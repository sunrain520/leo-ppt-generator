# Deck 结构模板（内容规划）

来源：`ppt-github/guizang-social-card-skill/references/content-planning.md`。用于把长文/材料压缩成一套 slide 的**结构骨架与文案节奏**，与风格模式（Editorial / Swiss）正交。

## 压缩阶梯

从原文逐层压缩，不把全文塞进画面：

1. **核心主张**：一句话。
2. **读者承诺**：翻页能得到什么。
3. **章节地图**：4-8 个想法。
4. **页面钩子**：短、具体、不抽象。
5. **正文片段**：只保留解释画面所必需的字。

> 画面集是「视觉大纲」，让读者想读正文/说明，而不是正文本身。

## 页面计划模板

```text
Title / Audience / Style / Image assets:

01 封面
  - Hook / Visual / 底部要点
02 内容页
  - 观点 / 文案 / 视觉 / 版式
...
```

## 好页面角色（避免重复同一卡片页）

钩子封面 · 问题场景 · 误区 vs 现实 · 清单 · 对比 · 产品截图证据 · 一句大结论/金句 · 分步流程 · 装备/购买清单 · 总结页（「记住这三点」）。

## 文案规则

- 标题朴素、锋利；避免「背景介绍」这类抽象标签（除非真的是上下文页）。
- 用**动词 + 后果**：「高帮鞋会让脚更闷」>「鞋子选择」。
- 产品更新：先讲用户可感知的变化，再给功能名。
- 户外：先讲体感问题（热/湿/滑/重/暴晒/迷路/冷）。
- AI/工具：先讲工作流变化（更快采集/更少手动/跨应用自动化/可编辑输出）。

## 封面钩子句式

「终于有 Mac 版了」「新手别急着买」「这个功能真的改变用法」「我替你踩过坑了」「先看这 5 个点」「不要被装备带着走」「从此不用手动…」。

**避免**：过长的完整文章标题、无具体对象的空洞 hype、一个封面塞多个无关主张。

## 图像主导序列（生活方式/图多内容）

```
P1   M16 图像主导封面  ← 最佳单图，整幅铺底，克制标题
P2   S11 / M05 / M10   ← 文字重：台账/清单/迷你数据（让眼睛休息）
P3   M02 素材笔记照片  ← 次佳图，放进框内，带说明
P4-N M02 / M11         ← 更多素材笔记或旁注随笔
末页 M07 / M04         ← 结语或金句
```

**硬规则**：绝不连续两张 M16。全幅封面后，眼睛需要先落在文字上。图主导不适用于新闻/教程/数据/评测（封面应是钩子句，用 M01 或 S01）；瑞士式产品/发布页的图是产品渲染或 UI 截图，用 S08，不用 M16。

## 页数参考

- 600–1000 字 → 5–7 页；1000–1800 字 → 7–9 页；极长源 → 压到 8–10 页，其余放进说明。
- 若多页下半留空过大 → 合并相邻想法。

## 视觉与内容的匹配

- 截图 = 功能/UI 证明；照片 = 场景/对象/人物/氛围；生成图 = 缺失场景/概念主视觉；图解 = 流程/链路/清单/系统关系。

生成图提示要短、按角色：

```
Editorial documentary photo, summer mountain trail, lightweight long-sleeve
outfit, natural sunlight, clean composition, no text, no logo.
```
```
Swiss conceptual product image, Android home-screen widgets generated by
natural language, clean off-white background, one IKB blue accent, no text,
no logo.
```

## 说明与元信息（小而复现，让整套有设计感）

- 分类行 `AI TOOL / UPDATE / 2026`
- 议题行 `SUMMER HIKING / BEGINNER GUIDE`
- 页码 `03 / 08`
- 紧凑标签 `DO` `DON'T` `WHY` `NOTE`

保持一致，用于**定向**而非装饰。

## 16:9 适配

- 压缩阶梯、页面角色、钩子句式、文案规则**直接适用**。
- 图像主导序列中的纵向配方在 16:9 下按 `layout-recipes` 转横向（M14/M15）。
- 页数参考按横向每页可容纳略多信息，5–9 页仍安全。

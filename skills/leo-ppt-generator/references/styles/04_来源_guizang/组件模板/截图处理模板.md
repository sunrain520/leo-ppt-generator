# 截图处理模板（Screenshot Treatment）

来源：`ppt-github/guizang-social-card-skill/references/screenshot-treatment.md`。用户提供 app / web / 代码 / 仪表盘截图时，**不要**裸塞进 `.frame-img`（比例错切 UI、硬边显 SaaS 味）。改用 `.frame-shot`。

## 何时用

- App/Web UI 截图（带状态栏/标签栏/工具栏/窗口 chrome）。
- 代码/终端截图。
- 需要每张标签可读的仪表盘/图表截图。
- 文字密度比构图更重要的 IDE 截图。

**照片类**（人/景/物）仍用 `.frame-img`；以下处理假定**像素级 UI 源、contain-fit 不可妥协**。

## 主体预处理

若源截图含浮动弹窗、桌面 chrome、被裁的侧边文字、光标轨迹、通知残片、背景 UI，**先裁到前景窗口/卡片**，再放进舞台。美化不引入透视/倾斜/旋转/3D 俯角（除非用户明确要 mockup 场景）；CleanShot 式处理是**正投影**：直、等比、安静背景、清晰安全内边距。

## 结构解剖

```
.frame-shot.r-{ratio}.corners-{sq|sm|md}.shadow-{none|soft|ed}
  .bg-{paper|grid|dot|grey-1|ink|asset-*}.inset-{none|sub|bal}
    └─ <img>   (默认 object-fit: contain)
```

可选包裹：`.device-browser`（桌面 chrome + 红绿灯点）、`.device-phone`（ink 色边框圆角）。

## 六参数（动手前一次定，不中途改）

### 1 `r-*` 比例
`r-16x10` app/web 默认（像真窗口）· `r-16x9` 宽视频/仪表盘 · `r-4x3` 经典桌面 · `r-3x2` DSLR 风 · `r-1x1` 图标/方形 widget · `r-3x4` 手机竖屏（配 `.device-phone`）· `r-21x9` 超宽/微信 hero。

### 2 `corners-*`（随风格锁定）
- Swiss 默认 `corners-sq`；只有周围有阴影/chrome 才 `corners-sm`。
- Editorial 默认 `corners-sm`(6px)；「剪纸」感可 `corners-md`(14px)。**绝不 >14px**（更大像 iOS 营销）。

### 3 `shadow-*`（随风格锁定）
- Swiss → `shadow-none` 90%；浮在 `bg-grid`/`bg-dot` 上才 `shadow-soft`；`shadow-ed`（加 1px 描边）留给 hero。
- Editorial → `shadow-soft` 在 `bg-paper-2` 上是暖默认；hero 用 `shadow-ed`。

### 4 `bg-*`（截图「舞台」）

| Token | Swiss | Editorial |
|---|---|---|
| `bg-paper` | 默认素舞台 | 同 |
| `bg-paper-2` | — | 默认暖舞台 |
| `bg-grey-1` | 默认素舞台 | — |
| `bg-grid` | 工程/数据 | 田野笔记工程 |
| `bg-dot` | 细结构 | 细结构 |
| `bg-ink` | 暗色 UI | 暗色 UI |

背景**绝不**用强调色；需要强调就加 `.t-cat`/`.kicker` 芯片，不 tint 舞台。

**9 张真实纹理 WebP**（`assets/screenshot-backgrounds/`，截图当页 hero 或素舞台显薄时用）：
- Editorial `style-a/`：`bg-asset-dune`（暖沙，旅行/生活方式）、`bg-asset-forest-ink`（深森林绿，暗 UI 配 ink-classic）、`bg-asset-indigo-porcelain`（冷青瓷，读写/设计工具）、`bg-asset-kraft-paper`（牛皮纸，笔记/手写 app）、`bg-asset-monocle-classic`（奶油纸，默认暖 hero 最像杂志）。
- Swiss `style-b/`（**只在强调色匹配时用**）：`bg-asset-ikb-dot`、`bg-asset-lemon-green-dot`、`bg-asset-lemon-grid`、`bg-asset-safety-orange`。

**经验**：不混强调色（`ikb` deck 不能拉 safety-orange 舞台）；纹理资产别再叠 `shadow-ed`；每 deck 一次决定是否用资产舞台（别只撒一张显像样本卡）；16:10/16:9 可安全裁剪，竖 `r-3x4`/方 `r-1x1` 优先素 `bg-*`。

### 5 `inset-*`（截图与舞台间距）
`inset-none` 填满 · `inset-sub`（Swiss 20px/Editorial 24px）默认 · `inset-bal`（48/56px）截图忙需安静时。

### 6 `fit-cover`（覆盖）
默认 `contain`（`.frame-shot` 的意义）。仅当 hero 背景图案、或用户明确要裁剪时加 `.fit-cover`。

## 安全区裁剪

全屏截图（iOS 1290×2796 / Android 1080×2400 / 桌面 1920×1080）：除非 chrome 就是主体，否则先裁掉状态栏（iOS 顶部 47-59px）、home 指示条（iOS 底部 34px）、桌面页面以上部分。裁不了就用 `object-position: center 6%` 下偏（工作区，非首选）。

## 风格速查（覆盖 80%）

```
Swiss 产品演示:   .frame-shot.r-16x10.corners-sq.shadow-none.bg-grey-1.inset-bal
Editorial 深挖:  .frame-shot.r-16x10.corners-sm.shadow-soft.bg-paper-2.inset-sub
Editorial hero:  .frame-shot.r-16x10.corners-sm.shadow-soft.bg-asset-monocle-classic.inset-bal
Swiss hero(匹配): .frame-shot.r-16x10.corners-sq.shadow-none.bg-asset-ikb-dot.inset-bal
```

对比图（before/after）两格**用同一套参数**——处理不同读作不一致，不读作对比。

## 16:9 适配

16:9 是截图天然画布（`r-16x9`/`r-16x10` 直接满幅），`.device-browser` 桌面 chrome 在横向 PPT 里最自然。`corners/sq vs sm`、`shadow-none vs soft`、`inset-bal` 的三档随 Editorial/Swiss 模式照用；9 张纹理背景在 16:9 下更安全（竖构图才需退素底）。

# 设计体系（元结构）

> 借鉴 `ppt-master`（hugohe3/ppt-master）的四轴正交模型，重构 leo-ppt 风格库的认知结构。核心结论：**风格不是「一个完整配方」，而是「几个正交轴的组合」**。

## 一、核心原则

### 1. 轴正交，任意组合

一个 deck 的最终视觉，由**四个独立轴**分别锁定，再任意组合：

| 轴 | 回答 | 例子 |
|---|---|---|
| **视觉风格** visual-style | 长什么样（形状/留白/纹理/排版） | swiss-minimal、glassmorphism、editorial、ink-wash |
| **论证模式** mode | 怎么论证（叙事骨架/页面节奏） | pyramid、narrative、instructional、showcase、briefing |
| **结构布局** layout | 什么画布 + 什么版式骨架 | 16:9 / 4:3 / 9:16 / 3:4 / 1:1 |
| **品牌身份** brand | 谁的身份（企业 VI / 行业惯例） | mckinsey、bcg、google、huawei |

> 关键区分：**视觉风格 = 长相；论证模式 = 论证**。任何模式可配任何视觉风格（一个 `pyramid` 结论先行的 deck，可以看起来 `swiss-minimal` 也可以 `dark-tech`）。「keynote 风」是**模式**（showcase 节奏），不是视觉风格。

### 2. 风格不带 HEX（行为与身份解耦）

视觉风格只描述**颜色如何被使用**（克制 / 局部 / 分 zone / 作标点），**不写死具体色值**。颜色身份由 deck 的 `colors` 单独锁定，风格只约束它的用法。

> 反例：旧库 139 个风格 brief 都写死了 HEX——它们把「风格（行为）」和「调色板（身份）」耦合了。整改方向：风格描述「怎么用色」，色值作为可覆盖的默认建议，不视为风格的固有属性。

### 3. 视觉风格 ↔ 图片渲染 配对

图片式 PPT 的关键：每个视觉风格配一个「图片渲染」风格，让 **AI 生成的图与 SVG 布局共享同一美学**。

| 视觉风格 | 配对图片渲染 |
|---|---|
| swiss-minimal | minimalist-swiss |
| glassmorphism | glassmorphism |
| blueprint | blueprint |
| editorial | editorial |
| memphis | flat |
| zine | screen-print |
| ink-wash | ink-notes / watercolor |
| sketch-notes | sketch-notes |

## 三、文档格式规范

新轴（论证模式 / 待补轴）采用 **markdown 分节**，非 JSON brief：

**视觉风格文件 · 六节**（`shape & decoration` / `typography` / `using colors`（不带 HEX）/ `texture & elevation` / `paired rendering` / `illustration propensity`）

**论证模式文件 · 四节**（`narrative skeleton` / `page-structure tendencies` / `speaker-notes register` / `page skeleton example`）

**信息图类型文件 · 三节**（`composition skeleton` / `text-policy variants` / `fewshot prompt snippet`）

> 旧库 139 个 JSON brief 保留为「整合版」可直接用；新轴逐步用分节格式落地，两者并存，后续按需迁移。

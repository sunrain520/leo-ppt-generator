# 论证模式：故事弧

故事弧说服。带听众走完 情境 → 张力 → 解决，用悬念、转折与人性化框架，让观点先打动情绪再打动逻辑。适合融资、案例、品牌历程、募资。

---

## 1. 论证骨架

**跨 deck 弧线**：情境 → 冲突 → 解决。设一个赌注、拉高张力、解决它、桥接到下一拍，不把完整弧线强塞进每页。

**悬念与回报**：在恰当时刻抛问题，在证据落地的那一拍揭晓。让好奇拉听众往前走。

**人性化框架**：把抽象观点锚在一个人、一个时刻、一个具体赌注上（「一个把三个月工期压到两周的团队」）。

**叙事推进**：用再框、揭晓、或赌注变化制造推进，让序列「移动」而非「重贴标签」。

标题读作推进弧线的拍子（「然后数字不再对得上了」），不是标签。

## 2. 页面结构倾向

- 按张力、回报与听众疲劳，交替「密」与「呼吸」拍，不机械交替。
- 视觉重量引导每拍（主图 / 一个焦点数字 / 一句金句）。
- 章节内连续，章节间变化。

> 结构服务弧线，不服务网格。本模式决定「每页的情绪拍子」。

## 3. 演讲备注语域

对话式——像在跟听众聊，不是读报告。页面内可按需用情境-冲突-解决。隐喻让抽象变具体（「像加了个涡轮」）。平实的反问制造悬念；每页从上一页桥接过来。口语化数据（「近三分之一」「翻了一倍多」）。

## 4. 页面骨架示例

```
第 3 页（转折）：全幅图 + 一行——「然后部署挂了。」
第 5 页（回报）：一个焦点数字 + 一句——「两周，而不是三个月。」
备注:          「先记住那个数字。现在告诉你它是怎么来的……」
```

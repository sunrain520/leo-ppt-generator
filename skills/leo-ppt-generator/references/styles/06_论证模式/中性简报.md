# 论证模式：中性简报

中性信息交付。把事实平铺、完整、可扫描地摆出来——没有要论证的论点、没有要讲的故事、没有要建立的课程、没有要制造的奇观。适合状态更新、参考 deck、目录、会议包、FAQ、数据参考。

---

## 1. 论证骨架

**刻意无论点**：deck 提供信息而非论证。当材料只是「这是事实」时，不要硬造结论先行（那是金字塔）或转折（那是故事弧）。

**主题标题，非断言**：页面标题平铺主题（「Q3 各团队人数」「支持的文件格式」）——查找清晰胜过说服性发现。这是金字塔断言标题的刻意反演。

**完整胜过选择性**：包含听众需要扫描的完整参考集，而非只放支撑某一立场的内容。覆盖即价值。

**平行、均等处理**：同级条目同形状、同权重，便于比较与快速定位；除非真的不同，否则不戏剧化任何一项。

**分节导航**：分组相关事实、标注组名、保持顺序可预测（时间 / 分类 / 字母），让读者跳到所需处。

## 2. 页面结构倾向

- 表格、定义列表、状态卡、参考网格、仪表盘——可扫描结构优于主视觉构图。
- 节内层级均匀；同级页版式一致，眼睛总知道往哪看。
- 当某数字真的重要（总数、状态旗标、异常）就突出它——但不造内容里没有的爆点。

> 本模式决定「页面完整而中性地把信息讲清」。

## 3. 演讲备注语域

平实、事实、朴素。陈述页面所示，不建张力、不逼「所以呢」。无反问、无悬念——听众可跟随或略读的清晰读出。数字平铺。

## 4. 页面骨架示例

```
标题: 「Q3 各工作流交付物」           ← 是主题标签，不是主张
正文: 状态表——工作流 | 负责人 | 状态 | 截止——各行等权重
备注: 「三个工作流在轨；支付在集成上有风险。」（平实读出）
```

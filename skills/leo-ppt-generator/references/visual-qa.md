# 视觉质检规范（图片式 generate 路线）

> 本文档是「五层非补偿质量门」中**「视觉呈现」层**的可执行展开。leo-ppt 已有
> 质量门框架（`image-deck-workflow.md` 第 10 步）与 worker 自查清单
> （`prompts/slide-worker.md`），本文档把它们整合成**闭环 + 对抗式审查 + 具体判据**。
> 判据阈值引用 [`styles/00_索引/通用设计规范.md`](styles/00_索引/通用设计规范.md)，不重复定义。

## 一、质检定位：对抗式审查，不是正向核对

「结构验证不等于视觉等价」。自动检查只证明确定性合同；**每页视觉质检必须是
「对抗式审查」**——主动假设这页有问题、专门找茬，直到找不到问题才判通过。
正向「照着清单打勾」会漏掉它没列出的错误。

借鉴：OfficeCLI 的「渲染→截图→对抗式审查」、PPTAgent 的逐页 `inspect_slide`
（不达标立即重做，不靠其他页通过来补偿）。

## 二、质检流程（闭环，缺一不可）

1. **worker 自查**（正向）：`slide-worker.md` 的 visually check 清单。
2. **父 Agent 独立复核**：不看 worker 的自述 `qa_note` 就下结论；亲自打开
   `origin_image/slide_<N>.png` 与 `prompts/slide_<N>.json` 逐条对照。
3. **对抗式审查**：按下节清单**专门找茬**，每条问「这一页最可能错在哪」。
4. **任一失败 → 打回该页重做**：改变输入/prompt/backend 后重试；其他检查通过
   不能补偿；「警告后继续」在视觉质量门上不成立。
5. **全部通过 → `image record`** + 写 `qa_note` + 留可复核证据路径（截图/对照）。

> 质检与「通用设计规范」的分工：后者是**生成时**的规范（怎么画得好）；本规范是
> **生成后**的检查（怎么验证达标）。

## 三、对抗式审查清单（找茬视角）

逐页过，任一条命中即失败：

**文字**
- 中文是否乱码、错字、漏字？
- 标题 / 数字 / 单位 / 标签 / 引用是否与 `slide_jobs.json` **逐字一致**？
- 有没有把「智能补全/实时协作」这类概念硬塞进数据图表并编造百分比？

**数据**
- 图表数值 / 单位 / 标签 / 图例 / 排序是否与 approved 完全一致？
- 有没有「无量化数据的内容用了 H-Bar/KPI 塔」这种**版式滥用**（编数据）？

**风格**
- 是否真正继承已批准样张（配色/字体/密度/纹理）？有没有逐页换风格？
- 大标题字重对不对（越大越轻；大标题被加粗 700+ = 失败）？

**图像**
- required asset 是否**可见**且**未被「重画近似」替换**？
- 主体（人脸/关键对象）是否被裁切？白底信息图是否被灰底包白图？

**版式**
- 有没有截断 / 遮挡 / 溢出（内容越过安全区）？
- 关键信息是否**只靠颜色区分**（必须同时有文字/标签/形状/位置第二线索）？
- kicker 是否压成大标题左右、而非上下结构？

**违禁**
- 有没有假 logo / 水印 / 页眉页脚 / 页码 / 角标 / 署名？
- 有没有 emoji 当图标？装饰性杂图（不解释任何东西的 SVG 圆/散点/光斑）？

**可读性**
- 投屏距离下字号 / 对比度是否达标？（阈值见下节）

## 四、视觉呈现具体判据（可执行阈值）

| 检查项 | 判据 | 来源 |
|---|---|---|
| 投屏字号下限 | 正文 18px / 卡片·caption·图注 16px / meta·kicker·图表标签 14px | guizang 瑞士风 |
| 对比度 | 正文 vs 背景 ≥ 4.5:1；蓝字压黑图 = 失败 | 通用设计规范 |
| 大字号限高 | `min(Xvw, Yvh)` 且 Y ≥ X×1.6；不限高导致溢出 = 失败 | guizang 对齐法则 |
| 截断/安全区 | 内容最低处不触及分页 nav，留 ≥3vh 呼吸 | guizang 对齐法则 |
| 字重阶梯 | 越大越细、越小越粗；同一页内小字字重 ≥ 大字字重 | guizang 排印 |
| 双重编码 | 关键信息不只用颜色，需第二线索 | 五层质量门 |
| 样张继承 | 配色/字体/密度/纹理与 approved 一致，不逐页换风格 | 五层质量门 |

## 五、质检结果记录

worker 返回与父 Agent record 时，`qa_note` 只写一句结论（通过 / 具体失败项），
并附可复核证据路径（截图或对照图）。失败按
[`reason-codes.md`](reason-codes.md) 给稳定 reason code 与恢复动作。

## 六、与现有环节的关系（不新建重复流程）

- 本规范**展开** `image-deck-workflow.md` 第 10 步的「视觉呈现」层，不新增第五层之外的门。
- worker 自查清单（`slide-worker.md`）保留为「流程①正向自查」，本规范补「②独立复核 + ③对抗审查 + ④打回」。
- 「现场验收」层（真实 provider / PowerPoint 桌面 / 投屏 / 人工审美）仍按原规范
  分别实际执行并记录，未执行写 `not-run`。

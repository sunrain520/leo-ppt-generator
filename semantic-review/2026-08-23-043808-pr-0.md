本审查只覆盖四个指定文件的本轮工作区增量（暂存区 -> 工作区）；相对 `main` 的差异包含先前整套新增功能，不能据此评价其他未提交工作。改动为配置状态服务接入受控凭据 reader，并尝试从当前解释器旁定位 `leo-ppt`，以便 materialize `config status --json` 的 `run_cli` 动作；发布测试也不再扫描 Git 忽略的 `.venv`。Watch for: **confirmed** direct `python -m` 在没有同级 console script 时仍会缺少 `ActionMaterializer`，且 Windows 的 `.exe` 入口不会被该回退找到。

## High-level view

**confirmed** 未配置的 provider 会要求一个 `run_cli` 动作。当前回退只检查 `Path(sys.executable).with_name("leo-ppt")`，既没有覆盖 Windows wheel 的 `leo-ppt.exe`，也没有定义“模块可导入但未安装 console script”的安全路径，故本轮目标的崩溃仍可达。

wheel 仍在临时副本中构建并检查 archive inventory；`third_party` 没有被复制忽略，仍受 archive 断言约束。文档的精确 skill-eval anchor 未断开，测试环境凭据由 `monkeypatch` 隔离。

## Test gaps

**likely** direct-module journey 只断言返回 JSON，继承测试解释器与 PATH，未覆盖“可 `python -m` 但无 console script”或 Windows `Scripts` 不在 PATH 的情形。应在隔离环境下覆盖此调用，并断言 `primary_action` 可执行，或断言返回安全的 unresolved/launcher 动作。

**likely** Windows wheel fixture 仅断言 `venv/Scripts/leo-ppt.exe` 存在；还需由该 venv 的 `python.exe -m leo_ppt_generator config status --json` 执行。POSIX 还应覆盖同级 `leo-ppt` 存在但无执行位，确认不会输出无效命令。

### `python -m` 仍不能保证生成动作

`_config_service()` 在 `cli.py:1133-1138` 依次接受环境覆盖、`shutil.which("leo-ppt")` 和同级 `leo-ppt`。`pyproject.toml` 声明标准 console script，而 `tests/release/test_installed_routes.py:80` 也明确将 Windows entry point 定位为 `venv/Scripts/leo-ppt.exe`；因此 Scripts 不在 PATH 的 `python.exe -m` 调用不会命中当前回退。

这不是无害的空建议。`provider_selection_required` 的 reason catalog 要求 `run_cli` 的 `config change`；当没有 CLI 路径时，`ConfigService.__init__()` 保持 materializer 为 `None`，`readiness._materialize_action()` 随即抛出 `ValueError("run_cli action requires an ActionMaterializer")`。同一因果链适用于任意解释器加 `PYTHONPATH` 直接执行模块、且解释器旁没有脚本的 POSIX 环境。**confirmed** 该修复尚未覆盖所述执行模型。

### 普通文件会成为不可运行的恢复命令

`bundled_cli.is_file()` 只证明文件存在；`CommandRenderer` 随后只验证绝对路径和 shell 引用。**confirmed** POSIX 中同级 `leo-ppt` 若不可执行，状态命令仍会生成该路径的 `primary_action`，实际恢复时以权限错误结束，影响 `not_configured` 与 `invalid` 的修复流。

### Wheel、文档与凭据回归面

source-debris 现在只审查 tracked inventory，精确排除了 Git 忽略的 `.venv`；wheel 构建仍在隔离副本，archive inventory 仍拒绝 `third_party`、字节码、build 与 egg-info。因此未发现此次测试调整会使实际 wheel 残留静默通过。文档只改变断行，连续 anchor 保持；环境值则由 `monkeypatch` 恢复，新增 reader 不把原始 secret 编入状态协议。
